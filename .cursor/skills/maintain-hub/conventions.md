# Hub conventions

## What this repo is

A **living public index**. People come from YouTube or GitHub and should reach:

1. Watch (YouTube series)
2. Learn (Insight Veda chapters, by domain)
3. Practice (Insight Veda folios → domains → scenarios)
4. Connect (profiles, newsletter)

Canonical chapter and scenario text stays on [Insight Veda](https://insightveda.com/). This repo stores the catalog so it is searchable and durable when the site nav changes.

## Insight Veda tree (match the product)

**Learn** — domain → numbered chapters. More chapters land *in the same domain folder*.

Domains (keep these slugs):

| Slug | Name on Insight Veda |
| --- | --- |
| `agents-orchestration` | Agents & orchestration |
| `data-knowledge` | Data & knowledge |
| `tools-integrations` | Tools & integrations |
| `prompts-outputs` | Prompts & outputs |
| `security-guardrails` | Security & guardrails |

**Practice** — **folio** (named pack, 25 scenarios, five domains) → domain → numbered scenarios.

- Live folio first (today: Brass Vernier).
- Earlier folios stay below for practice.
- Coming-soon folios get a README only (today: Iron Stylus).

A chapter and a scenario that share a domain should link to each other. Do not treat YouTube’s Fictional Bazaar as a folio.

## Voice

AI engineering: the decision in the running system. Not “architecture lessons.” Not job-title theory.

## Public URLs only

Link `insightveda.com`, this repo, YouTube watch URLs, and CONNECT profiles.

Do **not** link the private studio used to record videos, even if you know the path.

## Published pages

Do not rewrite a shipped video or chapter stub to match later work. Add a **Later** note and link the new page.

## Out of scope

Other people’s course lists, interview banks, certifications, monthly paper feeds, private diagrams.
